For every new generated or added website image:

- Use descriptive, lowercase, hyphen-separated filenames before adding the asset to the site.
- Generated responsive derivatives retain the existing `_480w`, `_800w`, and `_1200w` suffix convention; apply the naming rule to the source basename.
- Include the main page intent when relevant, for example `bachata-congress-2026-milan-workshops.webp`, `bachata-social-dancing-milan-2026.webp`, or `devero-hotel-bachata-congress-2026.webp`.
- Prefer `.webp` for photographic, generated, and preview images unless a different format is technically required.
- Write natural, useful alt text in the page language based on the image's purpose and surrounding content, following [W3C image guidance](https://www.w3.org/WAI/tutorials/images/informative/). Mention the event, Bachata, Milan, workshop, artist, hotel, or social dancing context only when it conveys relevant information.
- For a portrait used to identify an artist, the artist's name alone is acceptable when it conveys the needed information. Describe relevant action or detail when the image communicates more, such as a dance demonstration. Do not append event, location, or SEO phrases merely to lengthen the text.
- Purely decorative images use empty `alt=""`; do not add keywords to decoration.
- Avoid generic filenames and uninformative alt text such as `image.png`, `preview.jpg`, `dancers`, `artist photo`, or `flyer`.
